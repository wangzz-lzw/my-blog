# welcome-page Specification

## Purpose
定义 `/welcome` 这页门面的契约：它承载什么、长什么样、动到什么程度、数据从哪来，以及它如何与站点的主题与外壳隔离。

## Requirements

### Requirement: 根路径即欢迎页

站点 SHALL 在根路径 `/` 渲染欢迎页，未登录用户直接访问即可看到完整内容；按时间倒排的文章列表 SHALL 位于 `/blog`；旧地址 `/welcome` MUST 以 301 永久重定向到 `/`，且不再单独呈现内容。

#### Scenario: 直接访问根路径
- **WHEN** 未登录用户打开 `/`
- **THEN** 返回 200 并渲染欢迎页，不跳转、不需要登录

#### Scenario: 旧地址收口
- **WHEN** 打开 `/welcome`
- **THEN** 返回 301 且 `location` 指向 `/`，不出现两份内容

#### Scenario: 文章列表的新地址
- **WHEN** 打开 `/blog`
- **THEN** 渲染原有的账本列表；欢迎页上的「进入博客」指向它

#### Scenario: 旧内链已更新
- **WHEN** 在文章页、标签页、登录页、个人资料页点击「返回」链接
- **THEN** 回到 `/blog` 而不是欢迎页

### Requirement: 一屏只讲四件事

欢迎页 SHALL 只呈现：站点标记、字标、一句定位、一行状态与入口；MUST NOT 出现文章列表、侧栏、评论区或分页。

#### Scenario: 内容克制
- **WHEN** 渲染 `/welcome`
- **THEN** 页面上没有文章条目、没有标签云、没有侧栏区块，只有标记、字标、定位句、状态行与入口

#### Scenario: 状态行是真实数据
- **WHEN** 站点有 N 篇文章、M 个在用标签
- **THEN** 状态行显示真实的 N 与 M，以及最近一次发布的时间；站点还没有文章时显示引导性文案而不是 0 堆叠

### Requirement: 固定白色，不跟随站点主题

欢迎页的外观 MUST 由自身作用域内的变量决定，`<html data-theme>` 在六套主题间切换时外观 MUST 保持不变；博客其余页面仍按主题渲染。

#### Scenario: 切换主题不影响欢迎页
- **WHEN** 把站点主题从「赛博青」切到「晨光白」后刷新 `/welcome`
- **THEN** 欢迎页底色、文字与强调色与切换前完全一致

#### Scenario: 不影响其它页面
- **WHEN** 在欢迎页引入的样式生效后访问文章页
- **THEN** 文章页仍按当前主题正确渲染，没有被欢迎页的变量覆盖

### Requirement: 霓虹只用于可交互处

强调色（电蓝、洋红）SHALL 只出现在可点击元素、焦点态与站点标记的笔画上；标题、正文与状态行 MUST 使用墨色与中性灰，页面不得出现大面积发光或渐变底色。

#### Scenario: 用色纪律
- **WHEN** 静态查看欢迎页
- **THEN** 霓虹色只出现在主按钮、次链接的悬停/焦点态与标记的两笔上，正文区域是白底墨字

#### Scenario: 对比度
- **WHEN** 用无障碍工具测量文字与背景
- **THEN** 正文与状态行对比度不低于 4.5:1，标题不低于 7:1

### Requirement: 入场动效只有一次

页面 SHALL 在首次加载时播放一段约 1.2 秒的入场序列（网格淡入 → 标记描边 → 光标块落下 → 字标逐字出现 → 定位句与入口就位），之后不再有随滚动触发的动画；唯一持续动作是光标以 1.2 秒步进闪烁。

#### Scenario: 一次入场
- **WHEN** 首次打开 `/welcome`
- **THEN** 上述元素按序出现，1.2 秒内全部就位，滚动页面不再触发新的入场动画

#### Scenario: 减弱动效
- **WHEN** 系统开启「减少动态效果」（`prefers-reduced-motion: reduce`）
- **THEN** 页面直接以最终状态呈现，没有位移、描边或闪烁动画，内容完整可读

### Requirement: 无需客户端 JS 也能读到全部内容

欢迎页 SHALL 在禁用 JavaScript 的情况下完整呈现文字、状态行与入口链接。

#### Scenario: 禁用 JS
- **WHEN** 浏览器禁用 JavaScript 后打开 `/welcome`
- **THEN** 标记、字标、定位句、状态行与三个入口全部可见可用（动效可以缺失）

### Requirement: 无障碍与键盘

页面 MUST 只有一个 `h1`，装饰性元素（标记、闪烁光标、网格）对辅助技术不可见，键盘焦点清晰可见且顺序与视觉顺序一致。

#### Scenario: 键盘遍历
- **WHEN** 只用 Tab 浏览
- **THEN** 焦点依次落在主按钮与两个次入口上，焦点环清晰可见，装饰元素不被聚焦

#### Scenario: 屏幕阅读器
- **WHEN** 屏幕阅读器读取页面
- **THEN** 只播报一次标题、一句定位与状态行，闪烁光标与网格不被朗读

### Requirement: 多档视口不溢出

欢迎页 SHALL 在 390 / 768 / 1264 / 1920 宽度下无横向滚动；一屏高度用 `100dvh` 计算，内容超出时允许纵向滚动而不是裁切。

#### Scenario: 手机
- **WHEN** 在 390px 宽视口打开 `/welcome`
- **THEN** 字标与定位句按 clamp 缩小，按钮不换行错位，页面无横向滚动条

#### Scenario: 矮屏
- **WHEN** 视口高度小于内容所需
- **THEN** 页面可纵向滚动，内容不被裁切，页脚仍可到达

### Requirement: 门面不挂站点头尾

欢迎页是门脸，SHALL 只渲染自己的内容：MUST NOT 出现站点页头（品牌行、导航、账号菜单）与页脚；离开这页的入口由页面自身提供。站点其它页面 SHALL 继续使用页头页脚。

#### Scenario: 根路径没有站点外壳
- **WHEN** 打开 `/`
- **THEN** 页面 HTML 里没有站点页头与页脚，只有欢迎内容与它自己的三个入口

#### Scenario: 其它页面仍有外壳
- **WHEN** 打开 `/blog`、`/tags`、`/login` 或任意文章页
- **THEN** 页头（首页 / 文章 / 标签 + 账号菜单）与页脚照常渲染且可用

#### Scenario: 页头导航
- **WHEN** 在站点内页查看页头
- **THEN** 导航为「首页（`/`）/ 文章（`/blog`）/ 标签（`/tags`）」，并在文章列表与文章详情页保持「文章」高亮
