# Proposal

## Why

`/blog` 现在是**整页（body）滚动**：页头 `position: sticky` 挂在文档流上，文章列表没有自己的边界，浏览器最右边的滚动条一动，整页（含右侧栏的标签云、热门榜、最近评论）一起往上走。结果是：

- 滚到列表中部时，右侧栏已经整块划出视口，标签云和热门榜在最需要它的位置反而看不见；
- 滚动条在浏览器窗口最右缘，与它实际控制的那一列（文章列表）隔着一整个侧栏的距离，视觉上「不知道自己在滚什么」；
- 列表一旦变长，页头虽然 sticky 却仍与内容共享同一个滚动上下文，后续想给列表加"到底了"提示、虚拟化或分页都无处落脚。

用户的要求很直接：**滚动条应该是文章列表自己容器的，不是 body 的**（截图中红框位置即列表右缘）。

## What Changes

- **列表列成为唯一滚动容器**：`.ledger` 拿到 `overflow-y: auto` + `overscroll-behavior: contain`，滚动条贴在列表右缘（红框处），并沿用站点的细滚动条样式；`.sheet` 撑满「视口 − 页头」的高度。
- **页头、页脚、右侧栏不跟着列表滚**：页头与页脚保持不动；右侧栏在自己的列里 `sticky`，内容高过视口时它自己单独滚，而不是把列表一起带走。
- **body 在这条路由上不再滚动**：靠容器高度收口（`body:has(...)` 限高 + 内部滚动），不做全局 `overflow: hidden` 一律锁死——其余路由（文章页、标签页、后台）行为**完全不变**。
- **无障碍与键盘**：滚动区带 `role="region"` + `aria-label` + `tabindex="0"`，方向键 / PageDown / Home / End 可直接滚；焦点环沿用站点 `:focus-visible` 样式，Tab 顺序不因此多出无法跳过的黑洞。
- **位置恢复**：从文章页按浏览器后退回到列表时，列表恢复到原来的滚动位置，而不是回到顶部。
- **「回到顶部」跟着换目标**：右下角那个浮动按钮现在滚的是 `window`，body 不滚之后就点不动了——它得改成滚"当前真正滚动的那一层"（列表页滚列表，其它页照旧滚页面）。
- **窄屏回退**：视口窄于 `1025px`（现有两栏布局收成单栏的断点）时退回整页滚动，避免手机上"两层滚动 + 地址栏抖动"。
- **无 JS 安全**：脚本不可用时，列表内容依旧完整可读、整页也能滚动（滚动容器只是不再限制高度），不出现"内容被裁掉且不可滚"。

## Capabilities

### New Capabilities

- `blog-list-scrolling`: 定义列表页滚动的归属与边界 —— 谁是滚动容器、页头/页脚/侧栏的相对关系、键盘与指针可达性、后退时的位置恢复、窄屏与无 JS 时的降级，以及"这条路由不产生 body 滚动"这条约束。

### Modified Capabilities

（无。其余页面与 `feedback-dialogs`、`auth-affordance` 的既有要求不变。）

## Impact

- **代码**：改 `app/(site)/blog/page.tsx`（列表容器加语义与类名）、新增 `components/blog/ListScrollPane.tsx`（恢复滚动位置 + 键盘可达的客户端封装）、`components/FloatTools.tsx`（滚动目标从 `window` 换成当前滚动容器）；改 `app/redesign.css`（滚动容器、侧栏 sticky、滚动条样式、窄屏回退）。
- **依赖**：无新增。
- **数据**：无。
- **风险**：`body { display: flex }` 与 `sticky` 页头的组合对高度传递敏感，`min-height: 0` 漏一层就会退化成整页滚动；`GsapReveal` 的外层 `div` 夹在 `main` 与 `.sheet` 之间，高度必须一并传下去；`useLayoutEffect` 里读 `scrollTop` 要避免首帧闪跳。
- **验证口径**：`tsc` 与 `build` 通过；1280px+ 视口下滚轮只滚列表、页头/页脚/侧栏不动、窗口滚动条不出现；键盘 Tab 到列表后方向键可滚；「回到顶部」在列表页点亮并滚回列表顶部；后退后位置还原；`<1025px` 时退回整页滚动且无横向滚动条；禁用 JS 后内容完整可读。
- **不在本次范围**：列表分页/无限滚动/虚拟化、文章页与标签页的滚动改造、移动端地址栏收起动效、给列表加"已到底"提示。
