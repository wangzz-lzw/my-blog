# Proposal

## Why

站上的 6.7 万字只有两个出口：翻列表找，或者用浏览器自带的页内搜索。前者靠标题猜内容，后者只认字面——
问「LangChain 的 Agent 和 Chain 有什么区别」时，页内搜索会一无所获，因为正文里从没把这两者放在一句话里说过。

读者真正想问的是**内容本身**，不是"哪篇文章含有这个词"。这需要一个能读完全部文章、按语义找答案的入口。

但"能回答"比"答得漂亮"更要紧。一个被喂了两篇文章就敢对任何问题下结论的机器人，比没有这个功能更糟：
它会用常识补上文章里没写的东西，而读者无从分辨哪句有据、哪句是编的。所以这个功能的**核心不是回答，是克制**——
找不到依据时明确说不知道，并告诉用户"我能回答哪些"，而不是拿通用知识糊弄过去。

## What Changes

- **全局问答入口**：任意页面右下角浮起的入口按钮，点开是全屏高度的问答面板（不是新页面，不打断当前阅读）。
- **流式输出**：回答逐字出现，先出"正在检索"的状态，再出正文；带停止按钮。
- **检索基线用全文检索**：把每篇文章切块建索引，用 PostgreSQL 的全文检索（`to_tsvector` + `pg_trgm` 做模糊补充）召回候选块。
  本地开箱即跑，零安装。
- **生产用真的向量检索**：`docker-compose.yml` 的 PG 镜像换成 `pgvector/pgvector:pg16`（同为 PG 16，
  数据卷可沿用），配 `EMBEDDING_*` 后由运行时探测自动切到向量召回。**本地 Windows 的 PG 18 装不上 pgvector，
  所以本地走全文、生产走向量**——这正是双模式要覆盖的场景。
- **切换不靠开关，靠探测**：三条同时满足（扩展已装 / embedding 已配 / 表里有非零向量）才用向量，
  否则静默回落全文。两条路对外行为一致（同样流式、同样引用、同样拒答）。
- **带引用回答**：每条实质性结论后面能追溯到具体文章与段落，界面上可点开原文位置。
- **有据才答**：检索结果的相关性不足时**不调用模型生成答案**，直接返回固定的"不知道 + 我能回答的范围"。
  这个判断由代码做（检索分数阈值），不由模型自述——模型说"我不确定"是概率，代码拦下来是确定性。
- **能回答的范围由数据决定**：把已发布文章的标题与标签汇成"我能回答的话题"，在拒答时展示给用户。
- **频率限制**：按 IP 与登录用户限流，避免被当作免费代理刷。

## Capabilities

### New Capabilities

- `ai-qa`: 站内知识问答的完整契约 —— 检索如何召回、什么条件下答、什么条件下拒、流式输出的时序与中断、引用的可追溯性、双检索模式的等价性、限流与降级。

## Impact

- **代码**：新增 `app/api/ask/route.ts`（流式 SSE 端点）、`lib/rag/chunk.ts`（切块）、`lib/rag/retrieve.ts`（双模式检索）、`lib/rag/answer.ts`（prompt 与流式生成）、`components/ask/*`（悬浮入口 + 面板 + 流式渲染）；改 `app/layout.tsx` 或在 `(site)` 布局挂入口、`app/globals.css` 与 `app/redesign.css`、`lib/ai.ts`（抽出可复用的流式调用）、`prisma/schema.prisma`（文档块表）。
- **数据**：新增 `DocChunk` 表（文章 id、序号、文本、可选的向量列）。向量列在**不装扩展时不能建**，所以表结构走两种形态：
  基线版本只存文本 + 全文检索索引，向量列由一条单独的、条件执行的迁移补上。回填脚本按现有文章生成块。
- **依赖**：不新增运行时依赖（流式用原生 `fetch` + `ReadableStream` + `TransformStream`）。
  向量模式需要 embedding 接口，配置**单独一组** `EMBEDDING_API_KEY` / `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL`，
  不复用 `AI_*`——对话与 embedding 常用不同供应商，合并会把两个独立决策绑死。三项缺一即回落全文。
- **风险**：中文分词质量（PG 默认分词器对中文按字切，召回不如向量）、切块边界切断语义、流式与 Next.js 运行时/反代的缓冲冲突、限流被绕过、向量模式与全文模式召回差异导致答题质量不一致、模型无视上下文乱答。
- **验证口径**：真实浏览器里提问能流式出字并可中断；问到文章里没有的内容时明确拒答且列出可答话题；问到文章里有的内容时回答带可点引用；两种检索模式在同一问题上都能返回合理结果；未配置 AI 时给出配置提示而不是报错；`tsc` 与 `build` 通过。
- **不在本次范围**：多轮对话的记忆与指代消解、把用户问题反馈回训练、语音输入、跨站检索、图表类回答、
  对同一问题做多轮追问改写、**在本地/裸机编译安装 pgvector**（生产改用自带扩展的镜像即可，
  不为 Windows 本地搭建编译环境）、embedding 模型的选型调优。
