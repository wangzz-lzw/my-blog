# Proposal

## Why

后台写文章页是「页头 + 元信息表单 + 左右分屏」，进入正文时上下已经被吃掉两百多像素、左右被后台侧栏再切掉一截，长文写作时编辑区实际只有两个窄条。写长文需要一个只属于正文的空间，而现在的页面没有这个出口。

## What Changes

- 编辑器增加「全屏写作」入口：进入后编辑区占满整个屏幕，优先调用浏览器原生全屏（无地址栏、无系统边框），环境不支持或被拒绝时自动降级为「站内铺满」（盖住后台侧栏与页头，仍在浏览器窗口内）。
- 全屏内只保留正文与实时预览两块，以及它们必需的编辑手段：Markdown 工具栏、编辑/分屏/预览切换、字符与行数状态、退出全屏按钮。标题、slug、标签、封面、摘要等元信息在全屏内不可见，退出后接着填。
- 三种退出路径都生效且状态互通：Esc、工具栏「退出全屏」按钮、浏览器自身退出（原生全屏的 Esc 或系统快捷键）。从任一路径退出后，页面按钮状态立即同步。
- 进出全屏不重置编辑器：已输入的标题、正文、标签、摘要、当前视图模式、光标与滚动位置全部保持，未保存内容不丢。
- 无破坏性变更：不改保存接口、数据模型、路由；不进入全屏时页面与现在完全一致。

## Capabilities

### New Capabilities

- `admin-editor`: 后台文章编辑器的写作视图契约 —— 正文/预览的视图切换、全屏写作的进入与退出、全屏内的极简内容与状态保持，以及不支持原生全屏时的降级行为。

### Modified Capabilities

（无。`auth-affordance`、`markdown-render` 的现有要求不受影响；预览渲染仍走同一条 Markdown 管线。）

## Impact

- **代码**：`components/admin/PostEditor.tsx`（全屏状态机、三种退出路径、工具栏入口）、`app/globals.css` 的 `.editor-*` 区块（全屏布局与站内回退），可能微调 `app/admin/layout.tsx` 之外的层级变量。
- **不涉及**：`/api/posts` 等接口、Prisma schema、认证与权限、ISR 策略、CI/CD。
- **平台差异**：`document.fullscreenEnabled` 与 `requestFullscreen()` 在桌面 Chrome / Edge / Firefox / Safari 可用；iOS Safari 上元素级全屏实际不可用，会走站内回退路径——这正是需要降级的原因。
- **验证口径**：`npx tsc --noEmit` 与 `npm run build` 通过；四条进出路径手测；六套主题与 390px 窄屏各目检一次；退出后表单内容与视图模式与进入前一致。
- **不在本次范围**：全屏内保存/发布（按讨论结论，全屏内不提供保存，退出后再保存）；自动保存与草稿；分屏比例拖拽；全屏偏好的跨会话记忆（浏览器要求用户手势才能进入原生全屏，自动进入会被拦截，记忆没有意义）。
