# Proposal

## Why

写文章默认是分屏：左边 Markdown 源码、右边实时预览。写长文写到一半，两个框的位置就彻底错开了——

- 左边滚到第 200 行，右边还停在开头的标题上；
- 想对照某段的渲染效果，得在一侧滚一遍、再在另一侧滚一遍，靠肉眼找同一段。

更根本的问题在**跨屏滚动没有任何对应关系**：源码一行是 `## 小节`，渲染出来是一个标题块加一段正文，行数与像素数根本不同比例。所以「两边滚到差不多的地方」这种靠比例的近似做法，在长文里很快就看不出是同一处了。

另外分屏时两根滚动条还是**两套外观**：左边是浏览器原生的 17px 灰条带箭头，右边是全站自绘的 8px 细轨读数尺。同一屏里并排放着，矛盾很扎眼。

## What Changes

- **按源码位置联动，不做比例联动**：给渲染出来的每个块级元素标上它在 Markdown 源码里的**起始行号**，于是「左侧某一行」和「右侧某个块」之间有了真正的对应关系，两个方向都按它来定位，长文也不会累积偏移。
- **双向联动 + 可关闭**：滚左边，右边跟到对应块；滚右边，左边跟到那个块的源码行。工具栏给一个开关，关掉后两边各自独立滚。
- **不互抢控制权**：联动产生的程序化滚动不会再反过来驱动对方（用来源标记 + 短窗口抑制），否则两边会互相推着跑。
- **用户操作优先**：谁在滚，谁说了算——指针/键盘落在哪一侧，就以那一侧为驱动方；正在被驱动的一侧不回头抢夺。
- **左侧换成同一套自绘滚动条**：textarea 的原生条隐藏（`scrollbar-width: none`），改用全站 `--sb-*` 那套视觉，并叠一根跟随滚动比例的读数尺——两根条终于同源同形。
- **降级**：关掉 JS 时 textarea 自己的原生滚动照常可用（只是没有自绘条和联动）；`prefers-reduced-motion` 下联动的滚动不做平滑动画，直接定位；触屏上两侧都是原生滚动，联动仍生效但不加过渡。
- **只在分屏下联动**：`编辑` 或 `预览` 单栏视图里，另一侧不可见，联动自动不生效（不报错、不空转）。

## Capabilities

### New Capabilities

- `editor-scroll-sync`: 后台文章编辑器分屏时的双栏滚动契约 —— 源码行与渲染块的对应关系怎么建立、联动方向与开关、由谁驱动与如何避免互抢、滚动条外观统一、单栏视图与非脚本环境的降级、以及联动的精度口径（跟随到块不与跟随到像素的区别）。

### Modified Capabilities

（无。`markdown-render` 的七条要求都不变——本变更不改渲染结果，只是在渲染时多写一个 `data-*` 行号属性；`admin-editor` 的视图切换、全屏、内容保持等契约也不受影响，本变更只在其分屏状态下补一条滚动行为。）

## Impact

- **代码**：新增 `components/admin/editor-scroll-sync.ts`（联动算法，纯计算，可独立测）；新增 `components/ui/PlainScrollbar.tsx`（给 textarea 这类原生滚动元素套一层自绘轨道）；改 `components/Markdown.tsx`（新增一个 rehype 插件，把 `position.start.line` 写进 `data-src`）、`components/admin/PostEditor.tsx`（接联动、开关、两侧 ref）、`app/redesign.css` 与 `app/globals.css`（自绘条与开关样式）。
- **渲染面**：`Markdown.tsx` 是文章页与后台预览**共用**的管线，加 `data-src` 会让前台文章页的 HTML 也多出这些属性。需要确认：不影响任何既有选择器与样式、不泄漏敏感信息（行号本身无敏感性）、文章页体积增量可接受（每块约 14 字节）。
- **滚动体系**：textarea 不是 OverlayScrollbars 的 host，`lib/scroll-pane.ts` 的 `viewportOf()` 对它不适用——联动这里直接读写 `scrollTop`，不走全站那套解析（否则会拿到错误的滚动层）。
- **性能**：联动在滚动事件里只做查表与一次 `scrollTop` 赋值，用 rAF 合并；块位置在内容变化后批量测量一次并缓存，不在滚动帧里读布局（与 `ListScrollPane`、`PostOutline` 同一套做法）。
- **风险**：两侧互相驱动的回声；`data-src` 对行内元素也写入会让属性过多（只写块级）；懒加载图片/字体切换让块位置在测量后漂移；全屏与站内回退两种模式下容器尺寸变化需重测；textarea 有软换行，视觉行与源码行不是一回事（只能按源码行对齐，这是本方案的精度边界）。
- **验证口径**：真实浏览器里左右各滚一次，另一侧落到**对应的源码块**（按 `data-src` 断言，不是"差不多"）；开关关闭后互不影响；快速来回滚动不出现抖动或回弹；单栏视图与无 JS 下无报错；六套主题下自绘条外观一致；`tsc` 与 `build` 通过。
- **不在本次范围**：按光标位置自动跟随（本次只做滚动联动）、两侧同步高亮当前段落、把 textarea 换成富文本/CodeMirror 之类带行号的编辑器、文章页前台的大纲联动、联动比例的个性化配置。
