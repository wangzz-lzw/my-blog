# Proposal

## Why

导入 Markdown 现在只搬文字。文档里的图片引用是**本地相对路径**（`./images/a.png`、`../assets/b.jpg`），
而浏览器在 `<input type="file">` 里只交出用户选中的那一个 `.md` 文件——它旁边的图片根本拿不到。
结果就是导入之后正文里躺着一堆死链，编辑器还得弹一句「请用「插入图片」重新上传」（`PostEditor.tsx:322`）。

这条提示本身也说明了问题：**导入和图片上传统共用一个手工步骤**。作者的活儿变成：导入 → 记住哪几张图 → 一张张找
→ 一张张点「插入图片」→ 手动把 markdown 里的路径换成返回的地址。图多的时候这一步比写文章还烦。

另一半是入口冗余。工具栏那个「插入图片」按钮做的事，粘一张截图或把图片拖进编辑器**已经做了**
（`onEditorPaste` / `onEditorDrop` 都走同一个 `handleImageFiles`）。多一个按钮就多一次点击，
也多一条要维护的路径。既然"在 markdown 里直接传"才是自然动作，按钮可以走了。

## What Changes

- **导入支持多选与拖入**：`.md` 可以和多张图片一起选（文件多选），也可以把整个文件夹拖进来。
  文件选择器接受 `accept=".md,.markdown,.txt,image/*"` + `multiple`。
- **按路径匹配并替换**：解析出正文里所有非 http/data/锚点的图片引用，用**文件名**（含相对路径的尾段）
  去匹配本次同时提供的图片；命中就把那段 markdown 图片语法替换成上传后的站内地址（`/img/<key>`）。
- **匹配不上就说清楚**：未能匹配的引用**原样保留**（不误删、不改写成空链接），并在导入结果里列出
  文件名与数量，让作者知道哪几张还没处理。
- **上传走既有接口**：复用 `/api/upload`（内容寻址去重、`kind=image`），不新增上传通道；
  已存在 OSS 的图片会被去重，重复导入同一份文档不会产生重复对象。
- **删掉「插入图片」按钮**：工具栏不再提供该按钮；**保留**粘贴与拖入（它们才是"在 markdown 里直接传"的正路），
  拖入图片仍然是插到光标处的 markdown 语法。
- **导入确认条补一行资源摘要**：在既有的「替换 / 追加 / 取消」旁边显示"将上传 N 张图片"，
  让作者在覆盖正文之前就知道要发生什么。
- **不做视频**：本次范围只到图片。`/api/upload` 仍只接受 JPG/PNG/WebP/GIF 且 ≤5MB。

## Capabilities

### New Capabilities

- `import-asset-localization`: 导入 Markdown 时把文档引用的本地图片搬进对象存储并改写引用的契约 ——
  接受哪些附带文件、按什么规则匹配、替换成什么形式的地址、匹配不上的如何保留、失败与部分成功如何呈现、
  以及重复导入的幂等性。

### Modified Capabilities

- `admin-editor`: 工具栏不再提供「插入图片」按钮（MODIFIED「全屏内只保留写作必需内容」以反映工具栏的组成），
  并显式移除该按钮这一条能力（REMOVED，附原因与迁移方式）。粘贴与拖入插入图片的行为保持不变。
  （其余七条要求——全屏入口、原生全屏降级、退出路径、内容保持等——不受影响。）

## Impact

- **代码**：改 `components/admin/PostEditor.tsx`（导入入口改多选、新增资源本地化流程、删按钮与 `imageFileRef`）、
  新增 `lib/asset-localize.ts`（匹配与改写，纯函数）、改 `lib/markdown-import.ts`（或在其旁边加一层，
  取决于实现时怎么分层——解析与改写分开更清楚）；`app/globals.css` / `app/redesign.css` 补确认条的一行摘要样式。
- **接口**：**不动** `/api/upload`。它已经能一次收一个文件，多图就是多次调用；并行发出、逐个报错。
- **行为面**：导入从"纯文本操作"变成"可能带网络上传的异步操作"。这会影响：
  - 原子性——上传中途失败不能留下半截正文（现有 `markdown-import` 的「原子性」要求要继续成立）；
  - 进度反馈——多图上传需要可见进度，不能点完没反应；
  - 确认条的时机——现在是"解析完就弹"，之后变成"解析 + 上传完再弹"，覆盖正文前的等待会变长。
- **风险**：文件名匹配的歧义（两个目录下有同名 `a.png`）；用户拖入整个文件夹时浏览器给的是 `webkitRelativePath`
  而多选文件没有；相对路径写法多样（`./`、`../`、无前缀）；大图多张时上传耗时长；`text/html` 里的 `<img>`
  不是 markdown 语法，本次不处理。
- **验证口径**：真实浏览器里拖入一个含图文件夹 → 图片被上传、正文引用全部替换为 `/img/…`、页面能渲染出来；
  部分匹配时未命中的引用原样保留且给出清单；同一份文档导入两次，第二次全部命中已有对象（`deduped`）；
  上传中途失败时正文不被写入；工具栏没有「插入图片」按钮，但粘贴/拖入仍能把图插到光标处；`tsc` 与 `build` 通过。
- **不在本次范围**：视频（mp4/webm）、`<img>` HTML 标签、远程 URL 图片的下载转存、zip 包导入、
  导入时自动压缩图片、把历史文章里的本地路径批量修复、`/api/upload` 的体积上限调整。
