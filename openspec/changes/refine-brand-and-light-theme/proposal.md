# Proposal

## Why

页头目前没有统一的对齐体系：`.site-nav` 不是 flex 容器，导航文字、主题按钮、用户牌、退出按钮各自用 `margin-left`（1.5 / 1.25 / 1 / 0.75rem）拼间距，且作为 inline 盒子按基线对齐 —— 仅带色点的主题按钮没有文字基线，于是整行在纵向上参差、横向上间距忽大忽小。主题下拉菜单从右侧弹出并盖住「标签」，菜单内标题的左内边距（0.85rem）与选项内容的左内边距（1.05rem）不一致，色点列与文字也不成一条竖线，读起来是"没对齐"。

配色方面，五套主题全部是深色（赛博青 / 午夜靛 / 余烬橙 / 苔原绿 / 樱雾粉），白天或强光环境下没有可用的高可读方案。站点名仍是占位式的「我的博客」，出现在页头品牌、浏览器标题与页脚，缺少辨识度。

## What Changes

- **页头导航对齐**：页头导航行改为单一 flex 布局（`align-items: center` + 统一 `gap`），移除导航项/主题按钮/用户牌/退出按钮/登录注册链接上散落的 `margin-left`；所有控件在同一水平中线上，间距一致；窄屏仍可换行或收窄而不重叠。
- **主题下拉对齐**：菜单锚定到触发按钮，色点列、主题名、勾选标记在各行严格对齐，菜单标题与选项左边界一致；不改菜单项的语义（`role="menuitemradio"` / `aria-checked`）。
- **新增亮色主题**：增加第 6 套主题（规划 id `daylight`，显示名「晨光白」），提供完整的一套亮色令牌，使正文、卡片、边框、输入框、代码块、霓虹装饰与 hover 态在浅色背景上仍然可读且对比度达标。
- **首次访问跟随系统偏好**：没有本地记录时，按 `prefers-color-scheme` 选择亮色或深色（仍是 `data-theme` 机制，首屏前置注入，不闪烁）；用户显式选过主题后以本地记录为准。
- **站点更名 `LZW.LOG`**：页头品牌（含故障字效 `data-text`）、`<title>` 默认值与模板、页脚版权行统一替换。
- 无破坏性变更：不改变任何 API、数据模型、认证流程与路由；已有用户的主题偏好继续生效。

## Capabilities

### New Capabilities

- `theme-system`: 主题令牌集合与主题切换行为 —— 可选的配色主题清单、主题持久化、首次访问的系统偏好回退、切换器控件与下拉菜单的可用性与对齐。
- `site-shell`: 站点外壳的品牌与页头布局 —— 站点名称在页头/浏览器标题/页脚的呈现，以及页头导航行中导航项与各类控件的对齐与间距契约。

### Modified Capabilities

（无。现有 `auth-affordance` 定义的是页头认证状态的呈现，本变更只调整布局与间距，不改其行为要求。）

## Impact

- **代码**：`app/globals.css`（主题令牌块、页头/导航/主题切换器样式）、`app/layout.tsx`（站点名、`data-text`、页脚、主题初始化脚本）、`components/ThemeSwitcher.tsx`（第 6 个主题条目、首访系统偏好解析）、可能微调 `components/HeaderAuth.tsx` 与 `components/LogoutControl.tsx` 的类名配对。
- **样式依赖**：全站颜色来自 CSS 变量派生，但存在少量硬编码 `rgba(0,0,0,…)` 阴影与 `rgba(255,255,255,0.014)` 扫描线，亮色主题下需要一并处理。
- **不受影响**：Prisma schema、迁移、NextAuth 配置、OSS 上传、ISR 缓存策略、CI/CD 流水线。
- **验证口径**：`npx tsc --noEmit` 保持通过；页头在 1280 / 1024 / 768 / 390 四个视口下无重叠溢出；六套主题逐一切换后正文与控件对比度 ≥ 4.5:1。
- **不在本次范围**：`auth-affordance` 中「用户牌点击进入 /admin」的表述与现行「点击进入 /profile」行为已不一致，属历史漂移，留待单独变更修正。
