# Proposal

## Why

文章页现在是「一条竖线到底」：正文最宽 34em，左侧 96px 的栏位只放得下日期块，读完一屏就再没有方位感可依。长文（这类带小标题的技术记录正是主力）有两个具体问题：

- **想跳读只能靠滚**：一篇五千字的文章里找某个小节，得一边滚一边盯标题；刷新回来还得从头找一遍。
- **不知道读到哪儿了**：正文的 h2/h3 在视觉上被压成同一档（字号只差 0.23rem），滚动时没有任何"这一节开始/结束"的提示，只有顶部那条 2px 阅读进度条在动。

页面本身不缺位置：`.article-shell` 是 860px 居中的单栏，正文 `--measure` 只有 34em（约 544px），宽屏两侧各有一大片空白。这块空白应该承担结构信息，而不是继续当留白——所以这次把**文章大纲**放到正文左侧。

## What Changes

- **新增文章页左侧大纲**（`/posts/[slug]`，只在此页）：按正文的 **h2 + h3** 两级生成，h3 缩进一级；固定在第一屏可视区（sticky），超出视口高度时大纲自己滚，不跟正文一起走。
- **点击跳转**：点条目平滑滚到对应标题，落点留出粘性页头的高度（不把标题压在页头下面），并把 `#锚点` 写回地址栏（用 `replaceState`，不产生历史记录、不触发页面跳动），可直接分享到某一节。
- **滚动联动**：滚动时高亮"当前所在的那一节"，用 `aria-current` 暴露给辅助技术；跨过标题的条目转成已读的弱化样式。定位一律走 `currentScrollPane()`（整页滚动在 `#app-scroll` 里，`window.scrollY` 恒为 0）。
- **标题来源不重复解析**：大纲读的是正文渲染后的 DOM（`.prose h2, .prose h3`），id 由 `markdown-render` 已经保证的 `rehype-slug` 产出，因此大纲与正文永远一致，也不会出现自造 slug 与真实 id 对不上的情况。
- **宽屏出现、窄屏消失**：≥1280px 显示；更窄时整块移除（不是折叠、不是抽屉），退回现在的单栏阅读。**少于 2 个标题时不渲染**——单个条目的大纲没有导航价值。
- **降级**：无 JS 时大纲为空、整块不占位（它是增强导航，不是唯一入口）；`prefers-reduced-motion` 时跳转改为瞬时定位；触屏上大纲仍可用（点按跳转 + 滚动高亮），但它自己的溢出滚动交还给系统。
- **不动正文排版**：不新增字体、不改 `--measure`、不改 h2/h3 的字号与间距；大纲用等宽体（品牌、日期、标签那一套"机器嗓子"），只在字号与颜色上取正文之外的层级。

## Capabilities

### New Capabilities

- `post-outline`: 文章详情页左侧大纲的契约 —— 收哪些标题层级、什么条件下出现/消失、条目与锚点的对应关系、当前节的判定与高亮时机、点击跳转的落点与地址栏行为、大纲自身的滚动与粘性边界、键盘与辅助技术语义，以及无 JS / 减弱动效下的降级。

### Modified Capabilities

（无。`markdown-render` 的"标题锚点"要求只是被**使用**——大纲依赖每个标题有稳定 id，但不改变这条要求；正文排版与渲染管线的契约不变。）

## Impact

- **代码**：新增 `components/blog/PostOutline.tsx`（客户端，负责扫描标题、sticky、scroll spy、点击跳转）；改 `app/(site)/posts/[slug]/page.tsx`（`.article-shell` 内加一层栅格与 `<aside>`，文章本体保持原结构）；改 `app/redesign.css`（新增大纲小节 + 在 1180px 断点里回退单栏）；大概率复用 `lib/scroll-pane.ts` 与 `components/ui/ScrollArea.tsx`，不改它们的实现。
- **布局**：大纲借用 `.article-shell` 左侧那块原本空着的留白（不把 shell 改成两列、也不加宽正文），因此**正文在任何宽度下的左缘位置都不变**——既不会整篇段落抖一下，也不会在正文右侧多出一块空白。代价是宽屏上看，整块内容不再严格居中（左侧比右侧多出一条大纲）。
- **滚动体系**：sticky 的参照物是 OverlayScrollbars 造的 viewport（`#app-scroll` 里那层），不是 document；中间任何一层出现 `overflow: hidden` 都会让 sticky 失效，需要沿祖先链核对。粘性偏移要避开 60px 的粘性页头，否则落点会被页头盖住。
- **无障碍**：大纲是页内导航，应作为 `nav` 并提供可读的标签；当前项用 `aria-current` 而不是只靠颜色；键盘 Tab 能到达每个条目，跳转后焦点落到目标标题上（或至少可见地提示位置）。
- **性能**：标题位置只在挂载、resize、内容高度变化时测量一次并缓存，滚动帧里只做比较与属性写入，不触发 React 重渲染（与 `ListScrollPane` 同一套做法）；正文里的图片懒加载会让标题位置持续变化，必须重测。
- **验证口径**：宽屏出现、窄屏消失、单标题文章不出现；点击每个条目都落在对应标题上方且不被页头遮挡；滚到文末时高亮停在最后一节；地址栏 hash 随点击更新、刷新后能直达；无 JS 与 `prefers-reduced-motion` 下不出现布局塌陷；`tsc` 与 `build` 通过；大纲出现前后正文左缘位置不变（实测 rect 像素值）。
- **不在本次范围**：h4 及更深层级、文档内搜索、大纲上的阅读百分比/分段进度、把大纲做成可折叠抽屉或悬浮按钮、给后台编辑器预览加同步大纲、多篇文章的合并目录。
